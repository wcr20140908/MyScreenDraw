# 6.1.0 Implementation Plan

**Goal:** Ship all requested document-safety, performance, export, page-management and classroom-preference improvements as 6.1.0.

**Architecture:** Preserve the existing canvas/page model, but make document ownership independent of whether the whiteboard background is visible. Add revision-keyed immutable persistence snapshots and safe background I/O. Reuse existing page rail and settings UI patterns.

**Tech Stack:** Python, PyQt6, pytest (QT_QPA_PLATFORM=offscreen), PyInstaller.

## Ordered work and verification
1. Add `tests/test_document_safety_610.py` reproducing exit/save page loss, restore loss, missing dirty state and destructive open; run it red; fix `main.py` and re-run.
2. In parallel, one sol agent owns `persistence.py` and `tests/test_persistence_610.py`: symmetric reader/writer validation and atomic failure preservation. Integrate its project-specific writer into `main.py`.
3. Add revision identity to pages and cache immutable serialized page data; background gzip/write after GUI snapshot; targeted tests must count serializations and verify edits during writes, failure retry, shutdown drain.
4. New export module: per-page streaming PNG/PDF with explicit outcomes, GUI progress/cancel and modal partial failure summary. Verify mid-page failure, bad destinations, cancellation, real PDF page count and no all-page bitmap list.
5. Import PDFs transactionally to independent pages; test rendering errors and cancellation do not corrupt the document.
6. Page metadata, duplicate placement, rename and drag reorder: retain stable identity/current page and serialized order. Add actual offscreen widget tests.
7. Benchmark strokes before cache implementation; measure cold/warm completed strokes and active stroke appends. Verify image equivalence and invalidation after erase/transform/undo.
8. Add recovery selection/preview and interval controls; monitor selection via synthetic screens; timer volume defaults and persistence tests.
9. Update version metadata/docs, run full offscreen suite, build package and isolated smoke/reopen checks; inspect release hygiene and publish release/tag/assets only after checks pass. Discuss teaching mode separately, without inflating scope.

For all tasks: write regression first, observe the failure, implement, inspect the diff, then record exact passing evidence in progress.md. Keep full acceptance matrix in task_plan.md; no release/completion claims from a partial suite.
