# 构建与发布 / Building and releasing

**当前工作树为 v6.3.0（2026-10-29）**。`version.py` 及构建/发布脚本统一使用 6.3.0。本页说明可复查的构建、打包与发布流程。

历史状态保留：**v6.0.1 已发布并回下载核验**，其构建门禁、隔离真实包重启、手动迁移及公开附件结果见 [6.0.1 验证记录](release-validation-6.0.1.md)。6.2.0 的下载与校验入口已切换为当前正式 Release。

下列清单用于各次发布重新核对，确保构建和发布输入一致；实屏触控等设备差异仍按实际环境记录。

## 准备构建

使用 Windows x64 和 Python 3.11 开发基线，先按 [贡献指南](../CONTRIBUTING.md) 创建虚拟环境：

```powershell
python -m pip install -r requirements.lock -r requirements-build.lock
python -m pip install pytest pytest-subtests
.\build.ps1
```

运行前确认 `build/` 和 `dist/` 没有需要保留的数据：脚本会清理这些目录。测试工具当前没有独立锁文件，应在验证记录中注明实际版本；不要声称整个环境已完全锁定或二进制可逐字节复现。

## 脚本实际做什么

1. 校验 `version.py` 与脚本中的版本门禁一致（当前锁定 `6.3.0`），清理旧构建树并在测试前记录打包源码快照。
2. 执行离屏 pytest 门禁，排除真实触控层。
3. 使用 `MyScreenDraw.spec` 生成无控制台、禁用 UPX 的 onedir 包。spec 在依赖分析期间将 System32 放在 PATH 前，避免外部工具的同名系统 DLL（例如不兼容的 ICU）污染产物；分析结束后恢复环境。
4. 检查许可证、Qt 平台/图片/PDF/SVG 依赖，以 `release_artifact.py check-package --root ...` 拒绝用户数据、截图、源码和运行日志混入，同时要求精确教学资源清单与源码哈希一致；冒烟前后都检查。
5. 执行构建目录中的 `--smoke-ui`，在函数内强制 Qt offscreen 并禁用软键盘启动，异常时也恢复调用方环境；清理验证产生的运行数据。
6. 写入 `RELEASE-MANIFEST.json`，包含应用版本、EXE SHA-256 和当前 `signature: none` 状态。
7. 打包 ZIP（排除 `data/`、`exports/`），执行 `release_artifact.py` 归档校验，再比对全部解压文件，并以同样的 offscreen 保护验证 EXE 启动与哈希。
8. 全部检查通过后，候选 ZIP 提升为正式文件名，同时保存 `.sha256` 和 `build/release-receipts/` 下的验收收据。收据绑定包、EXE 及打包源码；不是数字签名。

成功构建后输出为 `dist/MyScreenDraw/`、`MyScreenDraw-v6.3.0-windows-x64.zip` 和同名 `.zip.sha256`。ZIP 根目录直接包含 `MyScreenDraw.exe`、`_internal/`、许可证和清单；不能额外套一层目录，也不能上传源码 ZIP 冒充便携版。

发布流程要求测试、暂存 EXE、ZIP 完整性与解压文件核验、解压 EXE 启动、源码/提交/收据/校验和一致；上传前后再次只读核验，确保公开附件与发布提交完全一致。

### 6.2.0 递归源码与教学资源门禁

- `source_snapshot()` 不再只绑定根目录脚本：还递归绑定可导入源码包（包含 `teaching/`）下的 `.py`/`.ps1`/`.spec`，以及 spec 收集的全部教学资源。`data/`、`exports/`、`build/`、`dist/`、缓存、测试和文档不是二进制输入；发布仍要求整个工作树干净、每个输入由指定 HEAD 提交跟踪。嵌套源码或教学资源改动都使旧收据失效，不能只更新版本/哈希文件继续发布。
- `MyScreenDraw.spec` 与 `release_artifact.py` 共用 `teaching.packaging.collect_teaching_datas()` 的显式清单。资源收集允许 JSON、指定 images 图片及 fixtures 格式，拒绝不支持文件、符号链接、junction/reparse point 和硬链接。该层检查路径/类型，不代替 `CatalogLoader` 的目录语义检查或人工确认内容为合成教学素材。
- 对 6.2.0 及之后版本，包检查必须提供源码根目录且必须存在 `assets/tutorials/`。按清单映射的精确 `_internal/assets/tutorials/...` 路径和 SHA-256 比对 staging、ZIP 及解压内容，缺失、多余、改动字节均拒绝。不能因文件在 tutorials 目录内或是图片扩展名就一律放行；真实截图/名单不可伪装为教学 fixture。
- 归档仍检查路径穿越、重复/别名、文件目录冲突、类型/大小、CRC、x64 PE、依赖、清单和 EXE 哈希。验收收据绑定源码、ZIP、EXE 与构建检查；它既不是数字签名，也没有宣称原生实屏或教学逐章已通过。

## 下一版本必须同步的文件

- `version.py`：应用版本来源。
- `version_info.txt`：Windows 数值版本和完整 ProductVersion 字符串。
- `build.ps1`：硬编码版本门禁。
- `create_release.ps1`：版本门禁、标签、release notes 路径与 prerelease 标记。
- 中英文 README：源码版本与发布状态；便携下载链接及校验示例只指向已发布附件。
- `CHANGELOG.md`、对应版本的 release notes、`SECURITY.md`。
- 本页及其他描述“当前基线”的维护文档。

不要批量替换历史 release notes 的版本号。预览标签和 GitHub prerelease 标记应一致；正式版不能仍被标为预览。打包产物通过 Release 附件分发，不提交二进制包或用户数据到 Git。正式版保留发布说明，后续版本新增对应说明；不要删除或改写历史证据。历史清理记录：2026-10-03 已删除 v6.0.0-beta.1 至 beta.8 的说明文件。2026-10-05 已删除 GitHub 上全部 7 个预览版 Release（v5.0.0-beta.1、v6.0.0-beta.3 至 beta.8），包括发布说明、便携包和校验附件；正式版 Release、Git 标签及提交历史保留。历史变更见 `CHANGELOG.md`。

## 每次正式版发布验收清单

以下为每个最终候选包重新核对的验收清单；6.2.0 已按本清单完成并发布，后续版本继续逐项记录：

- [ ] 冻结功能；不存在已知的数据丢失、核心输入失效、崩溃或严重性能阻塞问题。
- [ ] [离屏回归](testing.md)通过，逐项解释跳过及未运行的测试。
- [ ] 最终 EXE 在目标触控大屏完成批注、鼠标穿透、多指、菜单、文字公式、白板和托盘验收。
- [ ] 用旧版配置和项目验证升级、独立笔形迁移、保存恢复；保留回退所需的数据备份。
- [ ] 验证下载失败、文件占用或权限失败时的更新行为，不损坏旧程序与用户数据。
- [ ] 完成长时间课堂使用和复杂页面压力验证。
- [ ] 记录 Windows 10/11、DPI 缩放、多屏、中文/空格路径、普通用户权限、无 Python 环境的实际覆盖范围。
- [ ] 验证断网及更新接口不可达时仍可启动和绘图。
- [ ] 校验便携 ZIP 内容、哈希、许可证、隐私清理和真实解压启动。
- [ ] 确认已知导出限制及未签名状态在用户文档中可见。
- [ ] 教学独立进程、epoch 结果判定、真实业务输入和原工作恢复分别验收；运行 `real_teaching_620.py` / `real_features_620.py` 的 actual native driver 前单独取得实屏授权，并保留负对照校准、失败/重跑及清理状态。源码原生驱动不代替最终 EXE。
- [ ] 无限白板逐页视图/缩放/锚点、负坐标与屏外内容保存和四格式导出、多列完整缩略图/跨行拖动/边缘滚动，以及教学提示遮挡逐项检查。
- [ ] 最终解压包包含与验收提交字节一致的完整教学资源；从该 EXE 验证教学入口/子进程/资源加载，不能只凭 `--smoke-ui` 或源码课程回归宣布完成。
- [ ] `CAPTUREBLT` 截图和原始输入日志/report 保留在私有 `.ccgui/` 等证据目录，不上传、不混入发行包；公开说明只保留脱敏摘要和必要哈希。

## 6.0.1 更新器专项门槛（历史场景，后续版继续回归）

- [ ] 下载状态独立于检查状态；下载期间重复检查或关闭设置不应错误清除下载状态或产生并行安装。
- [ ] 已知可信总大小显示百分比与字节进度；总大小未知时显示不定进度与已下载字节，不伪造百分比；下载结束仍须完成归档验证。
- [ ] 取消、网络失败、下载完成及校验失败各自正确清理状态和临时文件，取消后不进入安装，不改用户文件。
- [ ] 源码运行目录明确拒绝应用内覆盖安装，不改源码工作树。
- [ ] 便携安装传递目标版本与旧 PID；安全等待正确的旧进程完全退出。超时、无法确定进程身份或退出被取消时不得继续覆盖，不能以同名进程批量结束替代定向等待。
- [ ] 新 EXE 版本匹配目标，重启结果可验证；版本不符、重启失败、文件占用和权限失败等路径触发适当回滚并保留诊断，不能只凭启动命令已发出就宣布成功。
- [ ] 成功、取消和失败回滚均保留 `data/`、`exports/`、配置、名单、日志、自动保存及其他隐私文件；使用合成数据和前后哈希验证，不把真实数据装入包。
- [ ] 单独验证 **6.0.0 → 6.0.1 手动换目录迁移**。6.0.0 的运行中更新器有缺陷，新包不能追溯修老的下载/安装代码；不能将用新源码更新器跑通的事务作为旧版应用内升级成功的证据。

6.0.1 当时的发布说明要求明确：从正式 Release 手动下载并校验 6.0.1，解压到新目录；完全退出旧版后备份并复制 `data/`、`exports/`，不覆盖隐私文件；修改快捷方式及已启用的开机自启路径，运行新 EXE 并核对版本与重启。保留此历史迁移说明；6.2.0 正式附件已提供，使用当前 Release 直链。

## 发布与发布后验证

当前 `create_release.ps1 -Commit <完整提交哈希>` 要求本地包/收据/源码一致、干净工作树和远端提交可用，拒绝覆盖已有 Release 或目标不符的标签；先创建 draft，上传 ZIP/校验附件并再次核对输入后才转为公开。

6.0.1 的历史操作是先将 `v6.0.1` 标签明确绑定到已验收提交，再运行 `create_release.ps1 -Commit <完整提交哈希>`。原因是 GitHub 的 `/commits/<不存在的标签>` 可返回 422，而脚本仅将 404 视为不存在；预先推送正确标签可使原有门禁继续执行，不能通过忽略状态码或改写收据绕过。当前脚本仍保留这一状态码边界；今后若需预建标签，也只能在验收后绑定对应提交。若标签已存在，必须核对其目标，禁止强推覆盖已发布标签。

发布说明与验证记录按实际结果维护，构建、包哈希及必要的交互证据均由对应发布收据追溯。

6.2.0 正式附件已发布并回下载核验；中英文 README 的下载/校验示例、支持版本表及正式状态已同步。后续版本沿用同一门禁。

从 GitHub Release 下载实际附件，不要只检查本地构建目录。比对 ZIP SHA-256，在新目录解压验证启动，确认版本显示、EXE 和 `_internal` 完整。Release 首屏和 README 提供便携 ZIP 直链，并明确 GitHub 自动生成的 Source code 附件不能直接运行。

签名策略见 [代码签名说明](code-signing.md)。仅更新文档或创建 commit 不会更新已发布 ZIP；不要声称旧附件包含后来改动。

## 6.3.0 双平台发布

正式发布前，两平台 main 和 v6.3.0 标签必须绑定同一验收提交；发布后的纯文档跟进可快进 main，但不得移动已发布标签或重签/替换验收包。build.ps1 保留源码/教学资源/归档/EXE/收据门禁；签名工具只签署已有验收收据对应的字节，不能重新生成校验文件给未验收的包放行。

1. 提交并推送两平台 main，执行 build.ps1 完整验收；私有实屏和安装事务证据留在 .ccgui/ 或 .superpowers/。
2. 运行 python -B sign_update.py sign --commit <SHA> --key <本地 Ed25519 私钥路径>；私钥应在仓库元数据外部安全备份并保持本地，客户端只带公钥。
3. 验收后将两平台版本标签绑定同一提交；以进程环境 GITHUB_TOKEN / GITCODE_TOKEN 运行 python -B publish_release.py --commit <SHA>。凭据不得写入脚本、Git remote、日志或发布附件。
4. 脚本核对收据/签名/两平台提交，创建 GitHub draft 和 GitCode pre，分别上传 ZIP、.sha256、MyScreenDraw-v6.3.0-update.json，回下载核对后才发布。GitCode 使用官方 upload_url 返回的地址与请求头上传，source 类型自动归档不能当作安装包。
5. 正式发布后匿名重新下载两个平台的三个附件，比对同一 SHA-256；可用 --verify-public 单独复核。若中断，--resume 仅复用同标签、同名称、同说明且附件字节一致的发布，不删除或覆盖不同附件。

客户端使用选中的匿名 API，GitCode 不使用 GitHub 的 releases/latest 路径；6.3.0 起签名描述文件缺失或不符就拒绝候选，不静默回退到旧版本或另一线路。设置/历史说明和下载取消仍须回归。

本次 6.3.0 发布按用户要求只做离屏验收；构建收据之外，私有发布入口把最终 48 章教学、4 次计算器专项、冻结文档与升级结果的文件哈希绑定到同一 ZIP/EXE/源码提交的不可覆盖最终验收收据。签名、发布前最后复核和发布后均核对该收据，旧拒绝候选负对照必须失败。详见 [6.3.0 验收记录](release-validation-6.3.0.md)。此私有入口不替代通用构建收据，也不进入发布包。

2026-10-29：v6.3.0 已在两平台正式公开，六个公开附件均匿名回下载核对通过，客户端两条线路的检查、说明和完整下载均通过；公开解压 EXE 离屏冒烟退出码 0。验收提交为 `d12e1e03a379d574c64c1ddfb5fd9a8310ba0ec1`。实际结果和代理/限流恢复边界见 [6.3.0 验收记录](release-validation-6.3.0.md)。
