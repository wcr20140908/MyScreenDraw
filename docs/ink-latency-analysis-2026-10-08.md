# 笔迹落笔延迟分析与首轮优化

日期：2026-10-08（Asia/Shanghai）

## 测试限制

用户最新要求：**不要实屏**。已停止并关闭本轮启动的独立原生测试画布，没有进行原生点击、拖拽或笔输入注入。后续只做代码分析和离屏测试，未经用户重新授权不恢复实屏测试。

本报告的性能数字全部来自合成离屏 CPU 测量，不是物理笔尖到屏幕发光的延迟，不是冻结发行包验收。没有发布新版或修改 `v6.1.0` 资产。

## 原有绘制路径及瓶颈

1. Qt 输入事件进入 `DrawingCanvas.mousePressEvent`；PEN/MARKER 落笔前无条件调用 `capture_page()`，深拷贝全页笔迹、文字、图形和图片。
2. `_begin_stroke` 建立笔画，`add_smooth_segments` 按笔宽插值，将带 `QLine/QPen/id` 的短线段追加到 `all_segments`。
3. 移动事件最后调用无参数 `update()`，使整个画布成为失效区；`paintEvent → draw_content → draw_segments` 在 GUI 线程遍历旧笔迹并用 QPainter 光栅化。既有缓存保存的是几何路径，不是整页像素缓存。
4. 抬笔已经使用按笔增量撤销，却丢弃落笔前整页快照；还会再次使全部几何缓存失效，在白板中深拷贝全页，并扫描全页筛出当前笔画。这使抬笔的阻塞也会拖慢紧接着的下一笔。

## 本轮改动

- 普通笔、荧光笔和激光笔落笔不再创建无用的整页撤销快照；橡皮、选择变换等仍保留原撤销语义。
- 为当前鼠标/每根手指保存该笔线段引用，抬笔只处理本笔，不扫描所有历史笔迹。
- 书写移动只请求新笔迹及旧/新荧光笔光标的脏矩形；保留旧选择框消除、停笔反馈和其他工具重绘路径。
- 几何缓存增加有界空间格索引；小区域绘制先取局部候选，保留原绘制顺序。大范围路径进入有界后备集合，不因极端坐标建立海量格子。
- 追加型笔画完成后保留已构建的历史几何缓存。钢笔/毛笔出锋涉及原地改笔宽，暂保留全量失效保护。
- 白板书写抬笔不再立即深拷贝全页；真实文档仍保存在当前画布中。翻页、项目保存、导出和自动保存继续在明确读取边界同步当前页，`flush_pending_snapshot` 也支持待同步笔迹。不是丢弃数据，也不是把磁盘保存伪装为完成。
- 未改项目格式、笔迹数据精度或已发布版本号；仍然保留矢量内容，未改成降低质量的整页截图。

## 可重复的前后对比

命令：

```powershell
$env:QT_QPA_PLATFORM='offscreen'
$env:MYSCREENDRAW_NO_KEYBOARD='1'
python -B tests/benchmark_ink_latency.py --output .ccgui/ink-latency-2026-10-08-after.json
```

条件：800×800 离屏 Qt 画布、普通笔、预先生成并预热的几何缓存；100000 条短线段由 1000 笔组成；6 次移动输入；真实输入处理函数、实际 paintEvent、私有临时 telemetry 路径。计时不包含物理驱动、系统输入队列、显示器刷新或笔硬件。

范围：新低延迟与空间索引用例、既有笔迹缓存像素一致性、所有笔形、多指、停笔识别、白板与页面管理、文档安全、自动保存、笔形配置及默认值。测试文件均在 offscreen、无全局键盘监听、隔离数据路径下运行。不是整仓全量回归。

新测试还验证：各笔形和荧光笔的增量脏区绘制与完整内容绘制逐像素一致；多指抬笔不做全页快照，但项目保存包含全部接触点笔迹；翻页/导出无笔迹丢失；撤销/重做保留原笔画语义。

## 仍需注意的边界

- 冷启动、打开超大项目、整窗重新暴露和大范围擦除/变换仍可能需要全页工作，本次不是所有场景的常数时间渲染。
- 大量笔迹极端密集地落在同一格时，局部候选仍可能很多；这时可进一步评估像素分层/分块缓存，但不能直接宣称 GPU 是必要解法。
- 钢笔/毛笔出锋的全量缓存失效，以及自动保存时 GUI 线程的纯数据快照/序列化，仍是后续可单独优化的间歇性成本。后台写文件不等于后台完成所有快照工作。
- 当前改动在源码中；未更新用户已经打开的旧进程，未制作或发布新安装/便携包。
